它替你做什么，不替你做什么

这一节最重要。它负责把简历读透、排好序、给足证据。
判断和推进，始终由你来做。

它替你做

  • 批量拉当前列表，并补全常常只在详情页里的实习与项目经历
  • 逐条核对门槛：学历、院校、经验或实习、性别、年龄本地判定；语言和你手写的条件由 AI 对着简历核。满足＝过，明确不满足＝未过门槛，简历没提及＝「待确认」（不扣分，留给你人工核对）
  • 摘出经历证据，按「核心职责 / 业务场景 / 专业技能 / 责任范围」四项打分，在本地加权成匹配分，按决策分排序并写清原因
  • 把推荐 / 淘汰同步回 Moka、导出 CSV，并攒成本岗样本修正下一轮判断
  • 按职位记录「简历推荐对象」，一键批量推进多名候选人给用人部门（每个职位独立记录、互不串岗）

它不替你做

  • 不自动淘汰任何人。除非你亲手点，插件不会动任何人
  • 不看简历以外的信息：作品集链接、附件内容、面试印象都不在视野里
  • 不保证 AI 不出错，也不做背调。所以每张卡都给证据，方便你反驳它

第一次使用：装好并配通

只做一次。已经有人帮你装好，直接跳到下一节。

  1. 下载并加载插件文件夹

    到 github/gitlab 链接登录，下载最新的压缩包（zip）并解压，得到 moka-resume-plugin 文件夹。建议固定在同一个位置解压（例如下载目录下建一个 moka-plugin 文件夹），以后每次更新都覆盖到同一处，设置才不会丢。然后地址栏进 chrome://extensions/，开开发者模式，点「加载已解压的扩展程序」，选中这个文件夹。需要 Chrome 116 及以上。

  2. 打开侧栏

    登录 Moka，进任意职位的候选人列表，点工具栏里的插件图标。侧栏不会因为你点页面而关闭。

  3. 在「设置」里配好 AI 接口

    接口协议 / 提供商 / Endpoint / 模型名称都已由公司内网的 model router 统一配置并锁定，设置页只把它们显示成一条只读的「连接信息已预置」摘要，你只需要填一样：API Key。点一下 💾 保存并测试 一步完成保存 + 连接校验（成功 / 失败都会在按钮旁提示）。内网模型需在办公网或 VPN 下测试；Key 只存在你自己浏览器里。

设置页还有一组进阶项，默认够用 「评分并发数」默认 6，自建网关或本地模型可调到 8 提速、被限流时调小；「强制 JSON 输出」默认开启，网关不支持时会自动去掉该参数降级重试，不用手动关；「费用估算单价」已按内网模型预置（结果页的「预估花费」靠它算，别清空）。三项都收在「高级 · 测评参数与费用单价」折叠区里，平时不用展开。
以后代码更新了怎么升级？不会自动更新 维护同学把新版代码推到 github/gitlab 后，你浏览器里的插件不会自己变。升级要手动做一遍：到 github/gitlab 登录 → 下载最新压缩包 → 解压覆盖上次那个文件夹 → 回 chrome://extensions 点插件卡片上的「重新加载」→ 刷新 Moka 页面。

每轮筛选：五步

开筛后留意状态行的「已补全经历 N 位」——长期是 0 说明第一步没生效

第一步真的不能省 Moka 列表接口里经常没有实习经历，真实经历在详情接口里。跳过它，AI 只能看到自我评价，实习生和主动投递的人很容易被判成「无相关经验」。开筛后留意状态行的「已补全经历 N 位」，长期是 0 就回列表重新点开一位。

你填的三样东西，决定了结果好坏

岗位理解：AI 读 JD 读出了什么

「按 JD 刷新」后扫一眼岗位理解摘要——方向偏了，后面所有分数都会跟着偏。

硬性门槛：不满足就该往后排的条件

门槛是「一票压分项」，只填你真的会因此拒掉人的条件。把本该放「筛选关键词」的内容塞进门槛，会把一大批可看的人压到 49 分以下。

前四行由插件本地判定，后两行由 AI 对着简历逐条核对；判定结果分三态：过 / 未过门槛 / 待确认
门槛怎么判
学历按候选人最高学历比
院校211、985、双一流、留学生、QS100 多选，满足任一即过
经验 / 实习正式员工按工作年限区间；实习生看有没有相关实习或项目。简历里没写年限时记「待确认」，不扣分
性别 / 年龄年龄可多选、满足任一即过；简历里没这个字段时记「待确认」，不猜、不扣分
语言手写完整要求，如「日语 N1」。优先看实际使用证据（英文翻译 / 英文文档与邮件 / 英语环境实习都可算满足）；没写证书编号不会自动判没过，信息不足记「待确认」
专业及其他手写可核对的条件，如「设计类专业」「会用 Photoshop」（接受同义写法）。明确不满足才判未过，信息不足记「待确认」
「待确认」不是「不合格」 简历里没提及某项时，插件不会当成候选人不会（记 待确认，不压分），只有出现明确反向证据才判「未过门槛」并压分。看到琥珀色「待确认」，意思是这一条要你亲自去问。

筛选关键词：重点看定义匹配，加分看拉开排序

两者都不是门槛。重点看=想让 AI 优先核对的经历（如「品牌实习」）；加分看=有更好、没有也不扣的项，最多 5 项，每项 +3、最多 +15。

分数怎么读

卡片上只有一个大数字：决策分。它由门槛、AI 给的匹配分，以及符合条件时的加分看共同决定。匹配分不是让模型随手给一个总分，而是四项打分在本地按固定权重合成。

匹配分怎么来：AI 打四项分，插件按权重加总

① AI 给四项分别打分（各带理由）

40%
核心职责

干的活是不是岗位主线——权重最高，定基调

25%
业务场景

行业、客户、业务模式对不对口

20%
专业技能

要求的技能有没有实际用过的证据

15%
责任范围

承担的是主责还是纯执行

四项加总＝匹配分（0–100）。

核心职责为什么是底线？因为「干的活对不对口」，比「简历好不好看」更能说明问题。所以核心职责分偏低时，插件会给匹配分设一个上限——其他三项再高也冲不过去：

核心职责低于 40 分匹配分最高 49
核心职责 40–59 分匹配分最高 69
核心职责 60–79 分匹配分最高 84
核心职责 80 分及以上不设上限

举例：核心职责只给了 35 分，另外三项即使都很高，匹配分也会停在 49，进不了「可推进」（50 分起）——这样「title 很像、实际干的活不对口」的人就不会被误推上来。

为什么要有这个上限？（展开看理由）

匹配分是四项加权的：核心职责 40%、业务场景 25%、专业技能 20%、责任范围 15%。这有个漏洞——一个干活不对口的人，只要简历漂亮，后三项能拿高分，加权照样过 50。而「干的活不对口」恰恰是入职后没法弥补的那一项：行业可以迁移、技能可以上手学，唯独「做的不是这件事」没法在岗上解决。所以给它设一道硬上限：核心职责低于 40 分，匹配分最高 49，永远进不了推荐档；核心职责分越高，上限越松，80 分以上不设限。规则公开可查，被压分的人在「评分明细」里能直接看到是哪一项触发的。

两条补充：规则对所有人一致，历史偏好与反馈也绕不过它——偏好能调「重点看」，但不能凭空创造新的一票否决；如果某个岗位明显被误伤，正确动作是回头修岗位理解或「重点看」，让 AI 把实际干的活读准，核心职责分自然回来。

模型只给四项分与理由；权重、封顶、门槛换算全部发生在本地——同一份简历的分数不会飘

门槛全过，匹配 < 50 决策分 = 匹配分（四项加权） 加分看只提示、不计分，不能把不建议推进的人救到 50。
有门槛没过 决策分 = 49 − 7 × 未过条数 两条没过就是 49 − 14 = 35 分，最低到 0。差得越多，掉得越靠后。「待确认」不压分。
门槛全过，匹配 ≥ 50 决策分 = 匹配分 + 3 × 加分项 最多 5 项、+15，满分 100。可以跨过 80，卡片会单独标注「加分晋级」。没配门槛也按这一条计算。
侧栏标题里的「推荐 N」统计的是决策分 ≥ 50 的人数，以全部结果为准
决策分档位怎么处理
80 – 100优先推进门槛已过且经历明显对口，优先安排沟通
50 – 79可推进门槛已过、匹配尚可，读两栏证据后决定
0 – 49不建议推进门槛没过，或经历与岗位确实不对口。卡片会区分这两种情况

卡片默认只显决策分；点开「评分明细」能看到四项分与计算链——例如 匹配分 57 ＝ 52×40% + 55×25% + 62×20% + 66×15%。有门槛没过时档位行补一句「未过门槛 N 项（见差距）」；加分跨进优先推进时标「加分晋级」。

为什么留学 + 相关实习的人只有 45 分 先看卡片上有没有列出未过门槛。有，就是门槛在压分，跟经历好坏无关，去松一松门槛；没有，说明 AI 认为这段经历和岗位主责不对口，看右栏「差距」写了什么，再去调「重点看」或修 JD 描述。

它会越用越准，前提是决策留在侧栏

每次在侧栏点「推荐」或「淘汰」都会给这个岗位留一条样本——插件据此对齐下一轮评分，并把反复出现的分歧整理成可一键采纳的规则。

决策样本按岗位存在你本地并一直累计，同一个人重复点只更新一条；每个岗位最多 200 条、约 180 天过期。

「本岗校准」面板里有什么

入口是侧栏底部的 本岗校准 按钮：先给本岗决策统计（已决策 / 推荐 / 淘汰 + 分歧度），再按次数列出常见信号（反复未过的门槛、淘汰原因、未命中的加分看）。计数前会先做信号归一——「没有达人资源 / 缺少达人合作经验 / 无 KOL 合作经验」算同一个「达人合作」。

建议分两组：规则调整（可一键采纳，写入门槛 / 重点看 / 加分看，写入的是肯定式文案）与诊断（只提示，如「判定可能偏严 / 偏宽」）；每条附可信度 高 / 中 / 低。

看「它怎么给建议」的对照表
可采纳的建议落「规则调整」组（文案都可以先改短再保存），只提示的落「诊断」组
面板看到的情况它会建议
淘汰记录里同一条门槛反复缺加进「专业及其他」门槛（附提醒：写成硬性门槛会直接拦截没有该项证据的人）
插件推你却淘汰，且门槛都过了把反复出现的差距加进「重点看」
插件推你却淘汰，且多是「加分晋级」从「加分看」里去掉那一项（需该加分项曾把 ≥2 人送进推进档）
你推的人被某条手写门槛卡住放宽或删掉那条门槛
你推的人插件没推，但匹配本来够把反复出现的亮点加进「加分看」
你连续推荐的人匹配分普遍偏低、又没有门槛阻断诊断：插件判定可能偏严（只提示，不可采纳）
你连续淘汰的人其实没有门槛问题诊断：插件判定可能偏宽（只提示，不可采纳）
卡在学历 / 院校 / 年龄等下拉门槛只提示你去核对，不自动改

点「采纳并保存」会写入本岗配置并落盘，下次进这个岗位自动带出来；面板底部也可手写一条门槛或重点看直接保存。

样本太少时它不会乱给建议 不满 5 条决策只提示你继续积累；某一类分歧不满 3 次，不给那一类建议；同一个缺项要出现 2 次以上才会被整理成门槛；要移除某个「加分看」，需它曾把 ≥2 人送进推进档。判断一直一致时不会硬凑结论。用三五条样本去改门槛，比不改更危险。
回 Moka 手动推荐，这一条就不算样本 只有在侧栏点「推荐给用人部门 / 淘汰」才会记进校准和历史偏好。在 Moka 页面手动操作，流程照样走完，但插件看不到你的判断，也就学不到东西。

运行时：六个自助看板

除了结果卡，插件还提供几个「自助看板」。培训后遇到问题，多半能自己先定位。

运行日志

按 请求 / 推荐 / 筛选 / 评分 / 警告 / 错误 / 信息 分类（筛选按钮 5 类，「错误」含警告），会话级保留最近约 100 条；可暂停跟读、按类筛选、复制或导出。

排查快照

一键复制当前页面上下文、职位存档锚点和完整接口流水。反馈问题时贴这一份，基本不用再追问。

用时与费用

结果页首行只显「用时 X 分 X 秒 · 预估花费 ¥x.xxx」；调用次数与 token 收进日志与进度行。

评分并发

默认 6（设置页 1–8 可调）。遇到限流 / 超时自动降一档，连续成功后逐档回升，日志会写明实际并发。

评分失败

标明 timeout / overload / network / config；筛选结束自动补评一轮，仍失败可在卡片上单独「重评」。

已决策导出

导出当前职位的所有已决策简历（推荐 / 淘汰），带「同步状态」「决策时间」两列，文件名含职位名。

数据去了哪里

  • API Key、筛选配置和决策样本都存在你自己浏览器本地，不上传任何第三方服务。
  • 为了评分，候选人画像会发到你在设置里配的那个 AI 服务（OpenAI、Claude、公司自建或内网路由）。发哪儿由配置决定。
  • 插件不做任何使用行为统计，代码可在本地审计。
  • 候选人简历属于敏感个人信息。有合规要求时请用公司内网或本地部署的模型，并遵守公司数据管理规范。

注意事项

四个习惯，能避掉大部分误判

  1. 每轮筛选前先点开一位候选人详情

    重复强调，因为这是最常见的误判来源。

  2. 门槛只填硬条件，「最好有」放重点看

    门槛是压分项，关键词是提示项。「最好有品牌实习」应该写进「重点看」，不是「专业及其他」。

  3. 新岗位先跑 30～50 人试试

    小批量验证门槛和关键词配得对不对，再放开人数。人越多，耗时和 AI 调用成本越高。

  4. 决策留在侧栏点，也别只看分数

    在侧栏点才会攒成本岗样本，下一轮评分才会往你的偏好靠。分数负责排序，证据负责决策——两栏证据就是给你反驳 AI 用的。筛过三五轮后去看一次「本岗校准」。

几个容易误会的地方

同一个人重复筛选，分数一模一样

同一个人在同一套配置下的评分会缓存在本地约 7 天，重复筛选不会重复调用 AI，也就不会重复计费。改了门槛或关键词后配置变了，会重新评分。

卡片上写着「Moka 未同步成功」

说明你的推荐或淘汰在 Moka 侧没执行完，本地先记下了你的决定。再点一次同一个按钮就是重试同步，不会把记录清掉。等它同步成功后，再点同一个按钮才是撤销这次决定。

如果重试仍然失败，请到 Moka 里手动操作这一位，并把提示原文反馈给维护同学。

怎么批量推进多名候选人给用人部门

先在这个职位上、在 Moka 里手动批量分配一次（推荐给某位用人部门负责人），插件会记住这个职位的「简历推荐对象」。之后回到侧栏勾选多名候选人，点「批量推进」，插件会用记住的对象一键把他们都推进。推荐对象按职位独立记录，换职位要重新捕获，不会串到别的职位。

「推荐 N」和筛到的人数跟我预期不一样

「推荐 N」统计全部结果里决策分 ≥ 50 的人，不是屏幕上的卡片数，门槛没过的不计入。只筛到几十人时，先确认「本轮筛选人数」不是默认的前 50，需要全量选「全部」。

改了设置或门槛，结果没变化

顺序是：chrome://extensions 点「重新加载」→ 刷新 Moka 页面 → 确认侧栏配置还在 → 再开筛。

更新到新版本后，为什么设置、存档全没了，像重新装了一样？

Chrome 把「加载已解压的扩展程序」当成哪个插件，看的是文件夹路径。如果你每次下载压缩包后都解压到一个新目录（比如带着版本号的新文件夹），再「移除」旧插件、重新加载新路径，Chrome 就认为你装了一个全新的插件——本地存的 Endpoint、API Key、每岗条件、决策记录都会跟着旧插件一起清掉，只能重新配。

想保留设置与历史数据，记住一个动作：永远解压覆盖同一个文件夹（下载 zip 解压后，把里面的文件覆盖进上次那个 moka-resume-plugin 目录），然后只点「重新加载」，不要移除旧插件。这样配置和存档都在。

真不小心移除重装了，Endpoint / API Key 重填一次即可恢复使用；历史决策记录无法找回（只会影响「本岗校准」样本的连续性，不影响筛选本身）。

以前卡面上有「经历匹配 N」，现在怎么看不到了

卡面现在只留决策分一个数字。匹配分、四项分（核心职责 / 业务场景 / 专业技能 / 责任范围）与计算链都收进了卡片下方的「评分明细」，点开就能看到「匹配分 57 ＝ 52×40% + 55×25% + 62×20% + 66×15%」这类完整推导，一处讲清所有数字的来源。旧缓存结果（没有四项数据）会自动回退显示「经历匹配 N」，不会开天窗。

卡片显示「评分失败」，是这个人不行吗

不是。评分失败通常是模型偶发输出异常（思考型模型偶尔把 JSON 截断，或输出里混进思考过程）。筛选结束会对失败项自动补评一轮；仍然失败的可以在这张卡上单独点「重评」。评分失败不会被当成 0 分评价，也不参与匹配分排序。

结果页只看得到用时和花费，调用了多少次模型在哪看

调用次数与输入 / 输出 token 已收进设置页「运行日志」和筛选中的进度行——结果页只留日常关心的「用时 + 预估花费」。模型没有收录单价、也没填自定义单价时，连这一行也会隐藏（避免给一个不准的数字）。

反馈问题时请带上这些信息 最快是：设置页 →「运行日志」底部 →「复制排查快照」，一份打包页面上下文、职位存档锚点与完整接口流水。实在没有，再补报错原文、职位名称、有没有点开过候选人详情、本轮人数、用的模型名。请不要把完整 API Key 或带 Cookie 的请求粘到群里。
