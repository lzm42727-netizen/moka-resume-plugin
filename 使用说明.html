Chrome 插件 · v1.3

Moka 智能简历筛选助手

在 Moka 候选人列表页自动拉取简历、按硬性条件标注、用 AI 做四维度评分，并给出推荐等级与理由。本页说明如何安装、日常使用，以及出错时如何排查。

1. 插件能做什么

  • 批量拉取候选人：从当前 Moka 列表接口翻页拉取，可配置本轮人数（30 / 50 / 100 / 200 / 全部）。
  • 详情补全经历：列表里常缺实习/项目经历时，自动用详情接口补全（含 practiceInfo / projectInfo）。
  • 硬性条件本地判定：学历、院校、经验、性别、年龄、实习经验等不满足会标注并置底，但仍会 AI 打分。
  • JD 解读 + 四维度评分：先解读 JD 给出建议权重，再按经验 / 技能 / 教育 / 潜力打分，本地加权得综合分。
  • 结果浮层：右侧面板按分数排序，展示等级、分维度分数与亮点/差距。
适用页面：请在 https://app.mokahr.com 的候选人列表 / 初筛页面使用。其他页面可能无法拉取列表。

2. 安装与加载

  1. 拿到插件文件夹
    本地路径一般为：/Users/你的用户名/.../moka-resume-plugin；或从 GitHub 克隆仓库后解压。
  2. 打开扩展管理页
    地址栏输入 chrome://extensions/，打开右上角开发者模式。
  3. 加载已解压的扩展程序
    选择整个 moka-resume-plugin 文件夹（需包含 manifest.json）。
  4. 更新后记得重新加载
    代码有变更时，在扩展卡片上点「重新加载」，再刷新 Moka 页面（否则旧的 content script 仍在跑）。
注意：更新权限后（如新增域名权限），Chrome 可能弹出授权提示，请点允许，否则自定义 API / OSS 简历抓取可能失败。

3. 配置 API

  1. 打开 Moka 页面后，点击浏览器工具栏中的插件图标。
  2. 切换到 ⚙️ 设置 标签页。
  3. 填写：
    • API 提供商：OpenAI / Claude / 自定义（OpenAI 兼容接口选「自定义」）
    • API Endpoint：如 https://api.openai.com/v1 或你们内网路由地址；插件会自动补全 /chat/completions
    • API Key：你的密钥
    • 模型名称：如 gpt-4o、或内网模型名
  4. 先点 🧪 测试 API，成功后再点 💾 保存设置。
本地私有配置：若你本地有 config.local.js（不入库），提供商 / Endpoint / 模型可能被锁定为内网值，只需填写 API Key 即可。

4. 日常筛选流程

  1. 进入正确页面
    登录 Moka → 打开目标职位的候选人列表（如「初筛」阶段），确认列表里已有候选人。
  2. （强烈建议）先点开一位候选人
    点击列表里任意一位候选人的姓名进入详情页一次，再回到列表。这样插件能捕获详情接口（含 scene），后续才能稳定补全实习/项目经历。
  3. 打开插件弹窗 →「🧑‍💼 筛选」
    选择职位、职位类型（正式员工 / 实习生）、本轮筛选人数。
  4. 检查硬性条件与权重
    硬性条件通常会按 JD 自动预填，可再改；权重可由 AI 按 JD 建议，也可手动拉滑块。
  5. 开始筛选
    点「🚀 开始筛选」。页面右侧会出现结果浮层，显示进度、推荐人数与每位候选人的评分。
  6. 查看与决策
    按综合分从高到低浏览；不满足硬性条件的人会靠后，但仍有 AI 评分可供参考。可随时点「⏹️ 停止」。

5. 硬性条件说明

条件说明
学历要求本科 / 硕士 / 博士及以上；按最高学历比较。
院校要求211 / 985 / 双一流 / 留学生 / QS 等，多选时满足任一即可。
经验要求仅「正式员工」时显示；按工作年限区间判定。
实习经验仅「实习生」时显示；要求有相关实习/项目等结构化经历。
性别要求可选男 / 女 / 不限。
年龄要求预设区间多选（如 20-25、25-30…），满足任一即可；不选则不限；仅当候选人有年龄字段时判定。
设计原则：硬性条件不通过 → 标注原因并排到后面，但不会跳过 AI 评分，方便你人工复核「边缘人选」。

6. 评分与等级

四个评分维度

  • 经验相关性：工作/实习/项目与岗位职责的匹配度
  • 技能匹配：工具、能力、业务技能
  • 专业与教育背景：学历、院校、专业相关度
  • 潜力 / 稳定性 / 加分项：成长性、证书、亮点等

综合分 = 各维度分数 × 你设定的权重（自动归一化）− 未满足必备项的柔性扣分（每项约 5 分，最多约 20 分）。

推荐等级

分数等级含义
≥ 75强烈推荐高度符合，优先沟通
50 – 74值得推荐基本符合，值得推进
35 – 49一般部分符合，差距明显
< 35不推荐匹配度偏低

面板标题里的「推荐 N」= 综合分 ≥ 50 的人数（值得推荐及以上）。

7. 结果面板怎么看

  • 标题：评分进度 · 推荐人数，例如 评分 30/30 · 推荐 8
  • 状态行：拉取中 / 解读 JD / 补全经历与评分 / 完成提示
  • 橙黄横幅（如出现）：提醒你先点开一位候选人详情，捕获详情接口后再继续
  • 每位候选人卡片：综合分、等级、四维度小分（悬停可看理由）、亮点 ✓ / 差距 ✕
  • 列表按分数自动排序；不满足硬性条件者偏后

8. 重要使用习惯（减少误判）

必做：每轮筛选前，先在列表里点开任意一位候选人姓名进入详情一次。实习生、主动投递人选的实习经历往往只在详情里，不点开容易被判成「无相关经验」。
  • 改完插件代码或设置后：扩展页「重新加载」→ 刷新 Moka 页 → 再筛选。
  • 人数越多，耗时与 API 调用越多；首次建议用 30～50 位试跑。
  • 同一人同一配置会走缓存，重复筛选可能不再重复扣费；若要强制重评，可微调权重或换模型后再跑。
  • 正式员工与实习生的硬性条件栏会切换（经验 vs 实习经验），选错类型会影响判定。

9. 出错后如何处理

遇到问题先看面板状态行 / 候选人卡片上的红色提示，再对照下面条目处理。

提示：请先点开一位候选人 / 橙黄横幅一直在

原因：还没捕获到详情接口模板，经历补全不完整。

处理：

  1. 在当前列表点击任意候选人姓名，进入详情页
  2. 等 1～2 秒后回到列表
  3. 横幅应变为「已捕获」并消失；若仍在，刷新页面后再点开一次并重跑筛选
未找到候选人 / 只筛到 30 人左右

原因：不在列表页、列表未加载完，或本轮人数选得太小。

处理：确认在候选人列表页并刷新；弹窗里把「本轮筛选人数」调大或选「全部」；先滚动/停留列表让 Moka 发出搜索请求后再开筛。

无法连接页面 / 请在 Moka 使用

处理：确认标签页是 app.mokahr.com；刷新页面后重开插件；扩展管理页确认插件已启用并「重新加载」。

API 测试失败 / 401 / 未配置 API Key

处理：

  • 检查 Key 是否正确、是否过期
  • 自定义地址是否可达；Endpoint 填到 /v1 即可（不必手写完整 chat 路径）
  • 首次访问新域名时，在浏览器弹出的权限框里允许访问
  • 公司内网模型需在 VPN / 办公网环境下测试
卡片显示「无法解析模型返回」

原因：模型输出被截断，或先写了一大段分析文字再给 JSON。

处理：

  1. 扩展重新加载后再筛一次（解析失败不会写入缓存，可重试）
  2. 换更稳的指令跟随模型，或提高服务端输出长度限制
  3. 若多人连续失败，在设置里换模型后重试

当前版本已做截断修复与宽松抽取；个别模型仍可能偶发失败。

AI 说「缺乏实习经历」，但详情页明明有

原因：列表数据里 experienceInfo 常为空，真实实习在 practiceInfo；若详情未补全，AI 只能看到自我评价。

处理：筛选前先点开候选人详情；看状态是否出现「已补全经历 N 位」。若 N 长期为 0，按上面「橙黄横幅」步骤操作。

推荐人数和肉眼看到的不一致

「推荐」只统计综合分 ≥ 50 的人；面板可滚动，下方还有更低分人选。标题里的推荐数以分数为准，不是当前可视区域内的卡片数。

筛选很慢 / 中途卡住
  • 人数 × AI 调用量较大时属正常；可先减人数试跑
  • 可点「停止」后缩小范围再筛
  • API 限流时插件会自动退避重试；持续失败请检查配额与网络
改了设置或代码不生效
  1. chrome://extensions → 插件「重新加载」
  2. 硬刷新 Moka 页面（建议关闭旧标签再开）
  3. 重新打开插件弹窗确认设置已保存
仍无法解决时：记下报错原文、职位名称、是否点过详情、本轮人数、使用的模型名，连同复现步骤反馈给维护者；勿在反馈里粘贴完整 API Key 或带 Cookie 的 curl。

10. 隐私说明

  • API Key 与设置保存在浏览器本地（chrome.storage）。
  • 为完成评分，候选人画像会发送到你配置的 LLM 服务（OpenAI / Claude / 自建或内网路由）。
  • 插件本身不另行收集使用分析；代码可本地审计。
  • 对数据合规敏感时，请使用公司内网或本地部署模型，并遵守公司数据规范。
