Moka 智能简历筛选助手

1. 插件能做什么

  • 批量拉取候选人：从当前 Moka 列表接口翻页拉取，可配置本轮人数（30 / 50 / 100 / 200 / 全部）。
  • 详情补全经历：列表里常缺实习/项目经历时，自动用详情接口补全（含 practiceInfo / projectInfo）。
  • 硬性门槛：学历、院校、经验、性别、年龄等由本地判定；语言、专业及其他由 AI 逐条核对。判定分三态——满足＝过、明确不满足＝未过门槛、简历没提及＝「待确认」（不脑补、不扣分）。
  • 筛选关键词：「重点看」定义经历匹配；「加分看」最多 5 项，有证据时每项 +3。
  • AI 匹配分：模型给「核心职责 40% / 业务场景 25% / 专业技能 20% / 责任范围 15%」四项分数，插件本地按固定权重合成匹配分；核心职责偏弱时保护封顶，title 像但活不对口不会被误推。
  • 结果侧栏：卡面只留决策分；匹配分、四项分与计算链收进「评分明细」折叠区，卡上常显「简历信息完整度」与「判断把握」。推荐 / 淘汰可同步回 Moka。
  • 批量推进：按职位记住「简历推荐对象」，勾选多名候选人一键推进给用人部门（每个职位独立记录，不串岗）。
  • 本岗校准：侧栏决策攒成本岗样本，下一轮评分先对齐你的口味，并把反复出现的分歧整理成可一键采纳的规则调整（每条附可信度）。
适用页面：请在 https://app.mokahr.com 的候选人列表 / 初筛页面使用。其他页面可能无法拉取列表。

2. 安装与加载

  1. 拿到插件文件夹
    到 GitHub / GitLab 登录后下载最新的压缩包（zip）并解压，得到 moka-resume-plugin 文件夹（本地路径一般为 /Users/你的用户名/.../moka-resume-plugin）。建议固定解压到同一个位置，以后升级都覆盖到同一处。
  2. 打开扩展管理页
    地址栏输入 chrome://extensions/，打开右上角开发者模式。
  3. 加载已解压的扩展程序
    选择整个 moka-resume-plugin 文件夹（需包含 manifest.json）。
  4. 更新后记得重新加载
    升级时：下载最新 zip → 解压覆盖上次那个文件夹 → 在扩展卡片上点「重新加载」→ 刷新 Moka 页面（否则旧的 content script 仍在跑）。
注意：需要 Chrome 116 及以上。本版改为侧栏，加载后请重新加载扩展并刷新 Moka。更新权限后（如新增域名权限），Chrome 可能弹出授权提示，请点允许，否则自定义 API / OSS 简历抓取可能失败。
升级务必覆盖同一个文件夹：Chrome 认定插件身份看的是文件夹路径。若每次解压到带版本号的新目录、再移除旧插件重新加载，Chrome 会当成全新插件——Endpoint、API Key、每岗条件、决策记录会一并清空。所以永远解压覆盖上次那个目录，只点「重新加载」，不要「移除」旧插件。

3. 配置 API

  1. 打开 Moka 页面后，点击浏览器工具栏中的插件图标，打开右侧栏。
  2. 切换到 设置 标签页。
  3. 只需要填两项（接口协议 / 提供商 / Endpoint 已由公司内网 model router 统一锁定，无需理会）：
    • API Key：你的密钥
    • 模型名称：内网网关下的模型名；同网关的不同模型可随时切换，改完即生效
  4. 点 💾 保存并测试，保存后会自动测一次连接，结果直接显示在按钮下方。
关于锁定的三项：接口协议 / API 提供商 / Endpoint 由本地私有配置 config.local.js（不入库）锁定为内网 model router 的值，设置页置灰、防误改，日常使用不用管。模型名称可照常修改；确需改锁定项请找维护同学。
公司内网模型需在办公网或 VPN 环境下测试连接；测试失败先确认网络环境，再检查 Key。
两个进阶项，默认够用：「评分并发数」默认 6（1–8 可调，被限流时调小）；「强制 JSON 输出」默认开启，网关不支持时插件会自动降级，无需手动关。

4. 日常筛选流程

  1. 进入正确页面
    登录 Moka → 打开目标职位的候选人列表（如「初筛」阶段），确认列表里已有候选人。
  2. 开始筛选前会自动识别详情接口
    若侧栏出现橙黄横幅，再点击列表里任意一位候选人的姓名打开详情一次（无需操作，打开即可）后回到列表，即可补全 scene 令牌。
  3. 点扩展图标打开右侧栏 →「配置」
    选择职位、职位类型（正式员工 / 实习生）、本轮筛选人数。侧栏点页面也不会关掉。
  4. 检查岗位理解、硬性门槛与筛选关键词
    「按 JD 刷新」会更新岗位理解，并预填可识别的语言、专业等门槛以及重点看 / 加分看。招聘官可继续增删；改完点「保存当前筛选条件」，或直接开筛（会自动落盘）。
  5. 开始筛选
    点「开始筛选」。侧栏会切到「结果」，显示进度、推荐人数与每位候选人的评分。左边仍是完整的 Moka 名单。
  6. 查看与决策
    按决策分从高到低浏览；不满足硬性条件的人会靠后，但仍有匹配分可供参考。结果页顶部只显本轮用时与预估花费（调用次数与 token 收进运行日志 / 进度行）。点卡片会在 Moka 打开该候选人；勾选后可「批量推进」。底部可「导出 CSV」；刷新后可点「查看上次结果」。可随时点「停止」。

5. 硬性条件说明

条件说明
学历要求本科 / 硕士 / 博士及以上；按最高学历比较。简历无学历字段时记「待确认」（不扣分）。点「按 JD 预填」会从 JD 识别。
院校要求211 / 985 / 双一流 / 留学生 / QS 等，多选时满足任一即可。简历无院校信息时记「待确认」。点「按 JD 预填」会从 JD 勾选。
经验要求仅「正式员工」时显示；按工作年限区间判定。简历没写年限时记「待确认」，不扣分。点「按 JD 预填」会从 JD 识别（如 3-5 年、三年以上）。
实习经验仅「实习生」时显示；要求有相关实习/项目等结构化经历。简历没提及相关经历时记「待确认」，不直接判不具备。
性别要求可选男 / 女 / 不限。简历无该字段时记「待确认」。点「按 JD 预填」会识别「性别：男/女」「仅限…」；写了不限则不填。
年龄要求下拉多选 20-25 / 25-30 / 30-35 / 35+ 四档，满足任一即可；不选则不限；简历无年龄字段时记「待确认」。点「按 JD 预填」会按 JD 的岁数区间勾选。
语言可手写多条，如「日语 N1」「英语 CET6」。AI 按完整条件逐条核对，优先看实际使用证据（英文翻译 / 英文文档与邮件 / 英语环境实习都能算满足）；没写证书编号不会自动判未过，信息不足记「待确认」。
专业及其他可填写「设计类相关专业」「会使用 Photoshop」等可核对条件（接受同义写法）。明确不满足才判未过，信息不足记「待确认」；能映射到学历等固定项的内容不会重复写入。

所有已配置门槛都参与最终判定；任一项「未过」，决策分按条数降到 49 以下。判定为「待确认」的项不压分——它只说明简历信息不足，需你人工核对。未填写的项目不参与门槛。

5b. 筛选关键词

栏说明
重点看希望 AI 优先核对的经历或技能，如「品牌实习」。缺失会影响整体匹配判断，但不是一票否决门槛。
加分看有则更好的经历或能力，如「作品集」。最多 5 项，有可核对证据时每项 +3、最多 +15；没有不扣分。

重点看只影响匹配判断，不按条计分。加分看只在门槛全过且匹配分 ≥ 50 时计入决策分；不能把不建议推进的人救到 50，但可以把可推进的人送进优先推进。两栏都可留空。

设计原则：硬性条件不通过 → 标注原因并排到后面，但不会跳过 AI 评分，方便你人工复核「边缘人选」。

6. 评分与等级

匹配分：四项加权，职责最关键

模型不再直接给总分，而是分别给四项打分并各带理由：核心职责 40% / 业务场景 25% / 专业技能 20% / 责任范围 15%；插件在本地按固定权重合成 匹配分（0–100），同一份简历不会因模型波动而漂移。核心职责是最高权重项，偏弱时匹配分会被保护封顶（<40 → ≤49、40–59 → ≤69、60–79 → ≤84），避免「title 很像、实际干的活不对口」被高分误推。四项分与计算链收在卡片的「评分明细」里。

决策分怎么算

  • 有门槛「未过」：决策分 = max(0, 49 − 7 × 未过条数)（两条没过＝35 分，最低 0）。「待确认」不压分。
  • 门槛全过、匹配分 < 50：决策分 = 匹配分（此时加分看只提示、不计分，不能把不建议推进的人救到 50）。
  • 门槛全过、匹配分 ≥ 50：每个有证据的加分看 +3，最多 5 项 / +15，决策分封顶 100。

加分跨过 80 时卡片会标注「加分晋级」。卡面只留决策分一个数字，匹配分与四项分收进「评分明细」；卡上另常显「简历信息完整度 N%」与「判断把握 高/中/低」两个把握度指标。

推荐等级

分数等级含义
80 – 100优先推进门槛已过且匹配明显强
50 – 79可推进门槛已过且匹配尚可
0 – 49不建议推进未过门槛，或经历 / 技能匹配不足

面板标题里的「推荐 N」统计决策分 ≥ 50 的人数（以全部结果为准，不是当前屏幕上的卡片数）。0–49 的卡片会区分「未过门槛」和「经历/技能匹配不足」；有门槛没过时档位行会补一句「未过门槛 N 项（见差距）」。

7. 结果侧栏怎么看

  • 标题旁状态：评分进度 · 推荐人数，例如 评分 30/30 · 推荐 8
  • 状态行：拉取中 / 解读 JD / 补全经历与评分 / 完成提示
  • 结果页首行：本轮用时 + 预估花费（模型未收录单价且没填自定义单价时整行隐藏；调用次数与 token 收进运行日志）
  • 橙黄横幅（如出现）：自动探测详情接口失败时，提醒你在左边点开一位候选人后再继续
  • 每位候选人卡片：左上大数字是决策分（卡面只留这一个分）；名字下方常显「简历信息完整度 N%」与「判断把握 高/中/低」。两栏证据为「亮点 / 差距」——差距里含未过门槛（红色「门槛」徽章）、简历找不到证据的要求（✕）与信息不足的「待确认」（琥珀色）。匹配分、四项分与计算链收进「评分明细」折叠区，点开可见。加分跨进优先推进时单独标注「加分晋级」。
  • 可按「待处理 / 推荐 / 已决策 / 评分失败」等过滤，并搜索姓名；评分失败卡片可点「重评」
  • 同岗位可点 本岗校准 复盘决策：建议分「规则调整」（可采纳，写回门槛 / 重点看 / 加分看，可改文案后再保存）与「诊断」（只提示，如「判定可能偏严 / 偏宽」）两组，每条附可信度 高 / 中 / 低

8. 重要使用习惯（减少误判）

必做：每轮筛选前，先在列表里点开任意一位候选人姓名进入详情一次。实习生、主动投递人选的实习经历往往只在详情里，不点开容易被判成「无相关经验」。
  • 改完插件代码或设置后：扩展页「重新加载」→ 刷新 Moka 页 → 再筛选。
  • 人数越多，耗时与 API 调用越多；首次建议用 30～50 位试跑。
  • 同一人同一配置的评分会写入本地缓存（约 7 天），重复筛选可能不再重复扣费；若要强制重评，可换模型后再跑。
  • 正式员工与实习生的硬性条件栏会切换（经验 vs 实习经验），选错类型会影响判定。
  • 决策要在侧栏点「推荐给用人部门 / 淘汰」才会攒成本岗样本（在 Moka 页面手动操作不算数）；筛过三五轮后看一次「本岗校准」。

9. 出错后如何处理

遇到问题先看面板状态行 / 候选人卡片上的红色提示，再对照下面条目处理。

提示：请先点开一位候选人 / 橙黄横幅一直在

原因：自动探测未成功，且还没捕获到详情接口模板，经历补全不完整。

处理：

  1. 在当前列表点击任意候选人姓名，进入详情页
  2. 等 1～2 秒后回到列表
  3. 横幅应变为「已捕获」并消失；若仍在，刷新页面后再点开一次并重跑筛选
未找到候选人 / 只筛到 30 人左右

原因：不在列表页、列表未加载完，或本轮人数选得太小。

处理：确认在候选人列表页并刷新；侧栏「配置」里把「本轮筛选人数」调大或选「全部」；先滚动/停留列表让 Moka 发出搜索请求后再开筛。

无法连接页面 / 请在 Moka 使用

处理：确认标签页是 app.mokahr.com；刷新页面后重开插件；扩展管理页确认插件已启用并「重新加载」。

API 测试失败 / 401 / 未配置 API Key

处理：

  • 检查 Key 是否正确、是否过期
  • 自定义地址是否可达；Endpoint 填到 /v1 即可（不必手写完整 chat 路径）
  • 首次访问新域名时，在浏览器弹出的权限框里允许访问
  • 公司内网模型需在 VPN / 办公网环境下测试
卡片显示「评分失败」（含失败类型）

原因：多为模型偶发输出异常——思考型模型（如 MiniMax-M2）偶尔把 JSON 截断，或输出里混进思考过程。日志会标明失败类型：timeout / overload / network / config。

处理：

  1. 筛选结束会对失败项自动补评一轮，多数会自行恢复
  2. 仍失败的，在这张卡上单独点「重评」
  3. 多人连续失败：检查网络 / 网关配额；必要时在设置里换模型后重试

评分失败不计入匹配分、也不当成 0 分评价；当前版本已做截断自动加倍重试、未闭合思考块剥离与网关降级重试。

卡片写着「Moka 未同步成功」

原因：你的推荐 / 淘汰在 Moka 侧没执行完，但本地已记下决定。

处理：再点一次同一个按钮就是重试同步，不会清掉记录；同步成功后，再点同一个按钮才是撤销这次决定。重试仍失败请到 Moka 里手动操作这一位，并把提示原文反馈维护者。

AI 说「缺乏实习经历」，但详情页明明有

原因：列表数据里 experienceInfo 常为空，真实实习在 practiceInfo；若详情未补全，AI 只能看到自我评价。

处理：筛选前先点开候选人详情；看状态是否出现「已补全经历 N 位」。若 N 长期为 0，按上面「橙黄横幅」步骤操作。

推荐人数和肉眼看到的不一致

「推荐」统计决策分 ≥ 50 的人。硬性门槛未过时决策分低于 50，不会进入推荐；卡片会用红标列出未过项。面板可滚动，标题里的推荐数以全部结果为准，不是当前可视区域内的卡片数。

筛选很慢 / 中途卡住
  • 人数 × AI 调用量较大时属正常；可先减人数试跑
  • 可点「停止」后缩小范围再筛
  • 并发默认 6（设置页 1–8 可调）；遇到限流 / 超时会自动降一档跑，连续成功再逐档回升（开筛日志会写「评分并发 N（设置上限 M）」）
改了设置或代码不生效
  1. chrome://extensions → 插件「重新加载」
  2. 硬刷新 Moka 页面（建议关闭旧标签再开）
  3. 重新打开插件侧栏确认设置已保存
仍无法解决时：记下报错原文、职位名称、是否点过详情、本轮人数、使用的模型名，连同复现步骤反馈给维护者；勿在反馈里粘贴完整 API Key 或带 Cookie 的 curl。

10. 隐私说明

  • API Key 与设置保存在浏览器本地（chrome.storage）。
  • 为完成评分，候选人画像会发送到你配置的 LLM 服务（OpenAI / Claude / 自建或内网路由）。
  • 插件本身不另行收集使用分析；代码可本地审计。
  • 对数据合规敏感时，请使用公司内网或本地部署模型，并遵守公司数据规范。
