# 结果卡片分数展示（规格）

日期：2026-09-01  
状态：已讨论锁定，实现前以本文为准  
范围：侧栏结果卡片文案与 CSV 列名。不计分公式、不改档位阈值、不改排序。

本文覆盖 `2026-09-01-gate-ai-match-scoring-design.md` 中「推荐与展示」对卡片必须同时写出「综合分、匹配分」的要求。计分与档位仍以那份规格为准。

## 目标

招聘官扫名单时只读一个决策分；跟用人部门解释时，只在「经历对口但硬条件不过」时看到经历匹配分。侧栏不再并排使用「综合分 / 匹配分」这对术语。

## 非目标

- 不改 `composeFinalScore`、门槛封顶公式、50 / 80 档位。
- 不改点卡片打开 Moka 详情。
- 不做点开才看到匹配分的二层面板。
- 门槛已过时不额外展示经历匹配分（两数相等，没有解释价值）。

## 术语

| 内部字段 | 侧栏对招聘官 | CSV 列名 |
|----------|----------------|----------|
| `score`（合成后的最终分） | 左边大方块数字，不标注「综合分」 | 决策分 |
| `matchScore`（模型经历/技能分） | 仅在被门槛压低时写「经历匹配 N」 | 经历匹配 |
| `level` | 档位原文 | 档位 |

内部代码与测试仍可用 `score` / `matchScore`。

## 卡片四态

左边大方块始终渲染 `score`。名单仍按 `score` 从高到低。

### 1. 可推进 / 优先推进

条件：`level` 为「可推进」或「优先推进」（即门槛全过或未配门槛，且 `score ≥ 50`）。

- 显示档位。
- 不显示「综合分」「匹配分」「经历匹配」。

### 2. 门槛已过但匹配不足

条件：`level === '不建议推进'` 且 `advanceReason === 'match'`。

- 显示档位。
- 下一行：「经历/技能匹配不足」。
- 不显示经历匹配分（此时 `score === matchScore`）。

### 3. 门槛未过

条件：`level !== '错误'` 且 `advanceReason === 'gate'`。

- 显示档位「不建议推进」。
- 当 `matchScore` 为有限数字且 `matchScore !== score` 时，写在档位文字后面：`经历匹配 {matchScore}`。两数相等则省略，避免重复。
- 下一行：「未过门槛」。
- 再下一行：未过门槛标签列表（`unmet[].item`，`reason` 放 title）。

对人可说的话：经历可以，硬条件不过，所以不能推。

### 4. 评分失败

条件：`level === '错误'`。

- 大方块可以是 0。
- 档位「错误」+「重评」。
- 下一行只显示失败原因（`scoreFailureMessage`）。
- 禁止渲染「综合分 0 · 匹配分 0」或任何把失败 0 分当成真实分数的括号提示。

## 删除的展示

`formatPenaltyHint` 不再输出「（综合分 X · 匹配分 Y）」。该括号提示从结果卡片移除。

经历匹配分的展示条件见上：只在态 3 且两数不同时出现。不要用旧 hint 函数继续拼两个术语。

## CSV

`SCREENING_CSV_HEADERS` 中原「综合分」「匹配分」改为「决策分」「经历匹配」。列顺序不变：

`姓名, 学历, 学校, 决策分, 经历匹配, 档位, 未过门槛, 亮点, 差距, 反馈, 链接`

单元格数值仍分别写 `score` 与 `matchScore`。失败行决策分 / 经历匹配可为 0，档位为「错误」；原因已在侧栏展示，CSV 不强制加原因列。

## 文档

`README.md` 与 `使用说明.html` 中面向招聘官的「综合分 / 匹配分」并列表述，改为与本文一致：侧栏主分是决策分；经历匹配只在门槛未过且两数不同时出现；导出列名为决策分 / 经历匹配。计分公式说明仍可写「门槛未过则封顶，否则等于经历匹配分」，但不要要求卡片同时标出两个术语。

## 验收

- 门槛全过、决策分 71：卡片有 71 与「可推进」，无「综合分」「匹配分」「经历匹配」。
- 门槛全过、决策分 32：卡片有 32、「不建议推进」、「经历/技能匹配不足」，无经历匹配分。
- 日语未过、经历匹配 90、决策分 42：卡片有 42、「不建议推进」、「经历匹配 90」、「未过门槛」及「日语」类标签。
- 评分失败：无「综合分 0 · 匹配分 0」，有失败原因与重评。
- 导出 CSV 表头含「决策分」「经历匹配」，不含「综合分」「匹配分」。
