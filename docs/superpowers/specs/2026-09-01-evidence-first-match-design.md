# 先证据后匹配分（规格）

日期：2026-09-01  
状态：已讨论锁定，实现前以本文为准  
范围：单次评分请求的提示词、JSON 契约、缓存版本。不改门槛封顶公式、不改决策分展示、不增加第二次模型调用。

计分与档位仍以 `2026-09-01-gate-ai-match-scoring-design.md` 为准。侧栏文案仍以 `2026-09-01-score-display-copy-design.md` 为准。

## 目标

模型必须先从简历抽出可核对的经历证据，再对照 JD 与重点看打匹配分。相邻方向的实习/项目不得仅因关键词字面缺失而被打到 50 以下。每人仍只打一次模型。

## 非目标

- 不拆成「先画像、再对照」两次 LLM 请求。
- 不改 `composeFinalScore` 的门槛封顶：`max(0, 49 − 7n)`；门槛全过时决策分仍等于 `matchScore`。
- 不把学历、院校、年龄、性别、年限写入匹配分。
- 不为经历证据新开结果卡片区块；证据并入现有「具备 / 未体现」。
- 不改硬性门槛的本地判定与手写门槛的过/不过语义。

## 提示词任务顺序

评分 user prompt 必须按下列顺序陈述，并写明禁止跳步：

1. 只根据【候选人完整信息】，为每段有实质描述的实习/项目各写一句证据（做了什么、面向谁、可量化结果）。简历没有的不要编。
2. 对照【岗位信息】与重点看，写亮点与差距。
3. 逐条核对手写硬性门槛（语言、专业及其他）。
4. 最后给出 0–100 整数 `matchScore`。

继续保留：逐条阅读每段经历（含实习、项目）；理由尽量引用具体证据；学历等由系统本地判定，匹配分不要因这些通过而加分，也不要重复扣分。

## 重点看 / 加分看

- **重点看**：用于对照与写理由。缺失可以拉低匹配分，但若简历有相邻经历，匹配分不得因此低于 50。
- **相邻**：同一职能大方向、职责有重叠即可。例如用户增长实习中的内容优化、用户访谈、线索转化，相对于「海外内容与创作者运营」算相邻，不是完全无关。
- **完全无关**：经历与 JD 主责不在同一方向，才允许匹配分低于 50。
- **加分看**：有则写入亮点；缺失不得把匹配分打穿。
- 档位仍按决策分：50–79 可推进，80+ 优先推进。相邻且门槛已过的人，预期落在可推进，而不是 40 多分。

对标自测（不写进 prompt 的数字，只作验收）：增长实习 + 小红书内容优化 + 海外用户访谈，对照「海外内容与创作者运营」重点看，门槛全过时 `matchScore` 应 ≥ 50。

## JSON 契约

只返回一个 JSON 对象：

```json
{
  "experienceEvidence": ["澳启教育：海外用户访谈 + 小红书内容优化，400+ 线索"],
  "matchScore": 62,
  "handwrittenGateResults": [{"item": "日语 N1", "met": false, "reason": "简历未提及日语能力"}],
  "highlights": ["亮点1"],
  "concerns": ["主要差距1"]
}
```

解析规则：

- `matchScore` 仍为必填；缺失则整单评分失败（与现网一致）。
- `experienceEvidence`：字符串数组，最多 6 条；缺省、非数组或解析不到 → 空数组，**不**视为 parseError。
- `handwrittenGateResults` / `highlights` / `concerns`：沿用现有归一化；手写门槛漏项仍按 `ensureHandwrittenGateResults` 判不过。

`normalizeModelScoreResponse` 须带上 `experienceEvidence`。合成结果可把证据并入 highlights 左侧展示：已有 highlights 时证据作为补充，不要挤掉模型写的亮点；highlights 为空时可用证据填「具备」列（仍最多侧栏现有条数上限）。

## 缓存

`PROMPT_VERSION` 必须改为与旧版不同的新字符串（例如 `evidence-first-match-v1`），使旧 `matchScore` 缓存全部失效。

## 验收

- 提示词含「禁止跳步」或等价的先证据后打分顺序，且要求输出 `experienceEvidence`。
- 提示词含相邻经历不得因重点看字面缺失而低于 50；完全无关才可低于 50。
- 解析：有 `matchScore` 无 `experienceEvidence` 仍成功，证据为空数组。
- 解析：无 `matchScore` 仍失败。
- 门槛封顶单测不因本规格而改期望分数。
- 侧栏卡片仍无「综合分 · 匹配分」并排；不新增独立证据区块的 DOM 结构要求（沿用具备/未体现即可）。
