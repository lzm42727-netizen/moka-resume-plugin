# 本岗校准对齐新打分（规格）

日期：2026-09-02  
状态：已实现

覆盖并修订 `2026-08-28-job-calibration-design.md`：不再给出权重建议；可采纳建议只对准门槛、重点看、加分看。历史偏好进评分 prompt 一并改到新术语。

计分本身以 `2026-09-02-bonus-keyword-scoring-design.md` 为准，本规格不改决策分公式。

## 目标

招聘官在侧栏点推荐 / 淘汰后，校准能告诉他**下次该拧哪颗旋钮**；下一轮筛同一岗位时，模型看到的历史偏好也用同一套语言（决策分、经历匹配、门槛、加分看），而不是旧的综合分 / 四维权重。

## 非目标

- 不恢复四维权重建议，不把 `readWeights()` 再接入校准。
- 不自动采纳、不静默改 preset。
- 不做全量复盘报表、候选人级时间线。
- 不把「匹配不足 50」解释成可用加分看救出。
- 不扩大 few-shot 条数（仍各最多 3 条），不把完整简历塞进偏好块。

## 插件建议推进的定义

`pluginRecommend === true` 当且仅当当时决策分对应档位为「可推进」或「优先推进」（决策分 ≥ 50）。与现网 `MokaScore.isRecommendLevel` 一致。

分歧：

- **over**：插件推、招聘官淘汰
- **under**：招聘官推、插件未推
- **agree**：两边同推或同不推

## 样本门槛

| 情况 | 行为 |
|------|------|
| 本岗决策 = 0 | 只提示「对本岗点推荐 / 淘汰后才会复盘」 |
| 1–4 条 | 只提示「已决策 N 条，满 5 条后给出规则建议」；仍展示六个数字 |
| ≥ 5 条 | 才允许给出可采纳建议 |
| 某一类分歧 &lt; 3 | 该类不给「改关键词 / 放宽门槛」建议 |
| 同一未过门槛文案 ≥ 2 次（出现在淘汰快照的 `hardMissing`） | 才建议加入专业及其他 |

权重相关阈值全部删除。

## 建议类型（最多 4 条，信息提示除外）

每条可编辑后点「采纳并保存」，写入本岗 preset 并落盘。已存在的相同芯片不重复追加。

### 1. 加入门槛 `addGate`

来源：淘汰记录里同一 `hardMissing` 归一化后出现 ≥ 2 次。  
写入：`hard.customGates`（专业及其他）。  
文案：可改短再保存。  
不写入语言栏，除非原文明显是语言条件且语言栏未满；实现时**默认只写专业及其他**，避免误判。

### 2. 放宽门槛 `relaxGate`

来源：under ≥ 3，且这些 under 快照里同一未过门槛出现 ≥ 2 次（`advanceReason === 'gate'` 或 `hardMissing` 非空）。  
写入：从 `customGates` / `languages` 中删除该条（精确匹配归一化后文案）。若该项在下拉门槛（学历等）里，**只给说明、不自动改下拉**，避免误删结构化条件。  
详情必须写清：这是「你推但插件因门槛卡住」的人。

### 3. 加入重点看 `addFocus`

来源：over ≥ 3，门槛已过（这些 over 的 `hardMissing` 为空或 `advanceReason` 不是 `gate`）。把他们 `concerns` 里反复出现的短语（≥ 2 次）收成一条重点看。  
写入：`focusKeywords`，上限 6；已满则建议改成「请先删一条重点看再采纳」，不覆盖。  
缺失的相邻经历问题用 concern 原文，不要发明新词。

### 4. 调整加分看 `dropBonus` / `addBonus`

- **dropBonus**：over ≥ 3，且这些 over 中 `bonusPromoted === true` 的人数 ≥ 2。建议从加分看去掉出现最多的那条已具备加分项（这些人被加分送进优先/可推进，但你淘汰了）。写入：从 `bonusKeywords` 删除。
- **addBonus**：under ≥ 3，且这些人 `bonusMetCount = 0` 但 highlights 里反复出现同一加分性质短语 ≥ 2 次，且当前加分看未满 5。建议加入加分看。不要建议用加分看去救 `matchScore < 50`。

### 5. 信息 `info`

无规则可给、或判断较一致时，沿用现有「样本还少 / 判断较一致 / 暂无决策」。

面板底部仍保留「自行新增专业及其他门槛」空白卡。可再加一张「自行新增重点看」空白卡；**不加**自行新增加分看空白卡，避免和「最多 5 项、不能救 50」的解释抢注意力。自行新增重点看若做，上限与芯片编辑器相同。

## 决策概览数字

六个数字保留：已决策、已推荐、已淘汰、与插件一致、插件推你却淘汰、你推插件未推。

「常见信号」扩展为最多 3 条，来源优先级：反复未过门槛 > 反复 concerns > 反复未命中的加分看。标签用原文，后面 `×N`。

过 ≥ 5 且 over 或 under ≥ 3 时，结果页摘要旁可以一句入口提示「本岗有 N 条分歧，可点本岗校准」，不自动弹开面板。

## 采纳写回

`applyCalibrationSuggestion` 按 `type` 分流：

- `addGate` → `customGateEditor`
- `relaxGate` → 从语言或专业及其他删除
- `addFocus` → `importantEditor`
- `dropBonus` / `addBonus` → `niceEditor`

成功后：preset 落盘、dock 成功提示、切到配置页便于核对（恢复 2026-08-28 规格里「切到配置页」；若当前实现只留在结果页，改为采纳后 `switchTab('screening')`）。

## 历史偏好进模型

`buildFeedbackContext` / `feedbackPromptBlock` 必须改掉「综合分」「上调相关维度」。

抽样：

- 推荐样本、淘汰样本各最多 3 条。
- **优先有分歧的条目**（over / under），不足再用时间倒序补齐。
- 每条一行，字段顺序：档位、决策分、经历匹配、加分看 x/y（未配置则省略）、未过门槛（无则省略）、一条 highlight 或 concern、若分歧则括号注明「当时插件未推 / 当时插件曾推」。
- `bonusPromoted` 为真时加「加分晋级」。
- **全岗聚合**写在样例之前（不占 3 条名额）：已决策 / 推荐 / 淘汰人数；有分歧时写「插件推你却淘汰 N」「你推插件未推 N」；反复信号最多 4 条（未过门槛优先，其次淘汰 concerns，同一文案 ≥ 2 次才出现）。个体样例仍各最多 3 条。

说明段改为：

> 开头是全岗统计，后面是样例。上述偏好优先于通用打分习惯。与「推荐」样本经历相近时，不要仅因重点看字面缺失把匹配分打穿 50；与「淘汰」常见差距重合时应在 concerns 写明。加分看是否具备由证据判定，不要把加分项写入 matchScore。不要机械复制历史分数。

`feedbackRev` 仍随决策变化，分数缓存继续失效。无需为此单独升 `PROMPT_VERSION`，但偏好块文案变了，旧缓存会在下一次决策后自然失效；**若实现时偏好块在无新决策时也要立刻生效，则同时升 `PROMPT_VERSION`。** 默认：升一次 prompt 版本，避免旧缓存继续带「综合分 / 维度」说明。

## 快照

校准与偏好都读 `sanitizeSnapshot`。至少保证这些字段能进历史（新决策开始有；旧快照缺字段时当 0 / 空，不报错）：

`score`、`matchScore`、`level`、`advanceReason`、`hardMissing`、`highlights`、`concerns`、`bonusKeywordResults`、`bonusApplied`、`bonusMetCount`、`bonusTotalCount`、`bonusPromoted`、`pluginRecommend`

旧 `dims` 可继续存，校准不再用来推断权重。

## 删除

- `inferDimFromText`、`avgDimScores`、`lowestDim`、`bumpWeight`、权重类 suggestion
- 面板对 `s.type === 'weight'` 的任何残留
- 校准调用 `readWeights()`

## 验收例子（独立推导）

1. 0 条决策 → 仅 empty 提示，无采纳按钮（除自行新增）。
2. 4 条决策全是 over → 提示样本还少，不给 addFocus。
3. 6 条决策，其中 3 条 over、concerns 均为「无达人合作」，门槛都过 → 一条 addFocus「无达人合作」类短句（可编辑）。
4. 5 条淘汰均缺「日语 N1」→ addGate「日语 N1」（招聘官可改短）。
5. 3 条 under 均因「学历本科」卡住且你仍推荐 → 不自动改学历下拉，只出 info「你推的人里有 N 人卡在学历，请到硬性门槛里核对」。
6. 3 条 over 且均为加分晋级、具备「作品集」→ dropBonus「作品集」。
7. 偏好块含「经历匹配」「加分看」，不含「综合分」「相关维度」。
8. 有分歧时，3 条推荐样本里至少优先列入 under，而不是只按时间最近的一致推荐。
