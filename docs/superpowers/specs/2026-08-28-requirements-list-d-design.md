# 本岗要求清单（方案 D）优化方案

> 状态：**实现中（核心链路已接，保存策略已拍板）**  
> 检查点：`v1.6.1` / `v1.6.2` 已推送。  
> 更新：2026-08-28 按产品拍板写入计分、预填/开筛、岗位理解布局；保存策略为显式保存 + 开筛落盘（表单改动不自动落盘）。

---

## 1. 一句话目标

选中职位后先给 **JD 岗位理解**，再据此维护本岗 **必须 / 重要 / 加分** 清单；开始筛选与综合分**只认这份清单**，不再背地使用未进清单的 JD importantHaves。

---

## 2. 配置页信息架构

自上而下（建议）：

1. **职位选择**  
2. **岗位理解**（可编辑：要做什么 / 核心技能 / 候选人素质；刷新后写入，可手改）  
3. **硬性条件**（结构化，默认红标不扣分，逻辑保持）  
4. **本岗要求清单**（三栏芯片）  
   - **必须**：未满足 −5 / 条，最多 6 条，扣分上限 **−30**  
   - **重要**：未满足 −3 / 条，最多 6 条，扣分上限 **−18**（含技能预填；素质也可写入，可手调）  
   - **加分**：具备 +5 / 条，最多 **3** 条，加分上限 **+15**；不具备不扣分（素质预填进本栏，可手调）  
5. **评分权重**：仅保留四维滑块**手动调整**；**不再单独展示岗位理解**  
6. 简历关键词已并入「重要」栏；结果卡名字下展示加分已具备 / 未体现  

「按 JD 预填」：刷新岗位理解，并预填三栏（可改可删）。

---

## 3. 综合分公式（冻结）

```text
匹配度 = 四维加权分（0–100 量级，现有逻辑）
综合分 = clamp( 匹配度 − 必须扣 − 重要扣 + 加分奖励 , 0 , 100 )

必须扣 = min( 未满足必须条数 × 5 , 30 )
重要扣 = min( 未满足重要条数 × 3 , 18 )
加分奖励 = min( 已满足加分条数 × 5 , 15 )   // 最多 3 条
```

结果卡提示示例：`匹配度 59 · 必须 −10 · 重要 −9 · 加分 +5`（无则省略该项）。

- 必须 / 重要未满足：可「忽略」加回该条扣分（与现网一致）  
- 加分不具备：仅「未体现」，无忽略、不扣分  
- 加分具备误判：走重评，不靠忽略  

---

## 4. 预填与保存（冻结）

| 动作 | 行为 |
|------|------|
| 按 JD 预填 | 写入**当前表单**三栏 + 岗位理解；**不自动落盘** |
| 改表单（芯片 / 硬性 / 权重等） | **不自动落盘** |
| 保存当前筛选条件 | 三栏 + 理解摘要 + 权重等写入本岗 preset |
| 开始筛选（未先点保存） | **视为已保存**：开筛前用当前表单执行一次本岗 preset 落盘，再按清单开筛 |

因此：预填后改完可以直接开筛，不必强迫多点一次保存；显式保存仍留给「只改配置不筛」的场景。

开筛时 `jobSpec` **仅来自本岗清单**（表单/刚落盘的 preset），禁止再合并「未进清单的 JD 暗项」来扣分或加分。

---

## 5. 旧数据迁移（已拍板）

- 旧「其他必备」`mustHaves` → `requirements.must`  
- **重要 / 加分**：迁移时若本岗尚无这两栏，**参照当前 JD 解读结果预填**（与「按 JD 预填」同源）；JD 解不出或没有对应项则**可空**  
- 预填进表单后的落盘规则仍遵 §4（显式保存，或开筛时默认保存）  
- **开筛计分**：只认清单里最终留下的项；不会在清单为空时再暗扣一套 JD important  

首次打开仅有旧 must 的岗位时：自动尝试补全重要/加分（有则填、无则空），并可用轻提示「已从 JD 补全重要/加分，可改后保存」。

---

## 6. 其它默认（可开工前微调）

- AI 预填 must 与手写必须：**合并去重**，手写已有的不覆盖文案  
- 重要 / 加分为 **0 条允许开筛**  
- 本岗校准「采纳」默认写入 **必须** 栏  
- 加分栏 UI 上限 3 个芯片（与计分一致）  

---

## 7. 数据形状（示意）

```text
requirements: {
  must: string[],       // ≤6
  important: string[],  // ≤6
  nice: string[]        // ≤3
}
jobUnderstanding: string  // 岗位理解摘要，随本岗保存
```

兼容：读旧预设时把 `mustHaves` 迁到 `requirements.must`。

---

## 8. 成功标准

1. 权重区不再单独出现岗位理解；要求区上方有理解摘要。  
2. 结果卡任意必须/重要扣分项，都能在对应栏找到（删栏后重筛不再扣）。  
3. 加分最多 +15，综合分不超过 100；不具备加分项不扣分。  
4. 预填未点保存就开筛：会落盘且本轮按当前三栏计分。  
5. 单测：分档扣/加封顶、迁移、开筛只认清单。  

---

## 9. 建议实现顺序（开工后）

1. `lib/score.js`：分档 cap + 加分奖励 + clamp 100；单测先红后绿  
2. `lib/persist.js`：`requirements` 迁移  
3. 配置 UI：岗位理解上移；三栏；权重区去掉理解  
4. `content.js` / 开筛：切断隐式 important；开筛前自动 save preset  
5. 结果卡文案、校准、使用说明  

---

## 10. 已拍板摘要

| # | 结论 |
|---|------|
| 加分 | 最多 3 条，每条具备 +5，累计最多 +15；综合分封顶 100 |
| 必须 / 重要 | −5/−30，−3/−18 |
| 预填 | 写入三栏；显式保存落盘；**开筛未保存则默认先保存再筛** |
| 岗位理解 | 从权重区移除；放到职位理解 → 要求清单链路；权重仅手动调 |
| 旧岗 | 其他必备 → 必须；重要/加分参照 JD 预填，没有可空；计分只认清单 |
