# 加分看计入决策分（规格）

日期：2026-09-02  
状态：已实现

覆盖并修订：

- `2026-09-01-gate-ai-match-scoring-design.md` 中「筛选关键词不算分」「加分看缺失不打穿」里「完全不计分」的部分。重点看仍不计分、不加分。
- `2026-09-01-score-display-copy-design.md` 的卡片旁注：有加分看填写时，四种非失败态都要能看到具备条数；加分真正计入时还要写出加了多少。

门槛封顶公式、50 / 80 档位阈值、重点看语义、先证据后匹配，均不变。

## 目标

门槛仍是「能不能进可推进」的硬线。加分看只在**已经可推进**的人之间拉开差距，并允许把「可推进」送进「优先推进」。匹配不够 50 的人，加分看再多也不能救出「不建议推进」，但卡片必须提示具备了几条。

## 非目标

- 不恢复「必须 / 重要 / 加分」三栏旧计分，不恢复四维权重。
- 重点看仍不是按条加减分；只定义经历匹配的对口标准。
- 加分看不能突破门槛封顶，也不能把经历匹配 &lt; 50 抬到 ≥ 50。
- 本规格不改本岗校准（校准对齐新分数另开规格）。
- 不加分看未填写时，行为与现在完全一致。

## 配置

- **加分看**最多 **5** 条（现有 UI / persist 上限 3 改为 5）。
- 每条具备 **+3**，合计上限 **+15**，决策分封顶 **100**。
- 空 = 不加分，也不展示加分旁注。
- 「专业及其他」仍是手写门槛，不是加分看。

## 谁判定「具备」

模型对照简历证据逐条输出，与手写门槛类似：

```json
"bonusKeywordResults": [
  { "item": "作品集", "met": true, "reason": "个人网站有 12 页内容作品集" }
]
```

规则：

- 有可核对证据 → `met: true`，计 1 条。
- 无证据、只有态度句或外链但正文看不到内容 → `met: false`，**不加也不扣**经历匹配。
- 招聘官填写了 N 条，模型漏了某条 → 该条视为未具备（与手写门槛漏判相同策略）。
- 具备条数 `metCount = min(5, 判定为 met 的条数)`。
- `bonusPoints = min(15, 3 * metCount)`。

`composeFinalScore` 只认归一化后的 `bonusKeywordResults`，不在本地做关键词字面碰撞。

## 计分

经历匹配 `matchScore` 仍由模型给 0–100 整数，只评价经历/技能与 JD、**重点看**的对口。prompt 须写明：加分看有无**不得**抬高或压低 `matchScore`。

```
未过条数 n ≥ 1：
  决策分 = max(0, 49 − 7 × n)
  加分看：不计分（bonusApplied = 0）

n = 0 且 matchScore < 50：
  决策分 = matchScore
  加分看：不计分（bonusApplied = 0）
  // 即使 bonusPoints = 15，也不能救出「不建议推进」

n = 0 且 matchScore ≥ 50：
  决策分 = min(100, matchScore + bonusPoints)
  bonusApplied = bonusPoints
  // 允许跨过 80 进入「优先推进」
```

档位仍按决策分：≥80 优先推进，50–79 可推进，&lt;50 不建议推进。

例：

| 门槛 | 经历匹配 | 加分看具备 | 决策分 | 档位 |
|------|----------|------------|--------|------|
| 未过 1 条 | 90 | 4/4 | 42 | 不建议推进（加分未计入） |
| 全过 | 45 | 3/3 | 45 | 不建议推进（加分未计入） |
| 全过 | 50 | 1/2 | 53 | 可推进 |
| 全过 | 78 | 1/3 | 81 | 优先推进（加分跨档） |
| 全过 | 86 | 0/2 | 86 | 优先推进 |
| 全过 | 96 | 5/5 | 100 | 优先推进（封顶） |
| 未配门槛、未填加分看 | 62 | — | 62 | 可推进 |

`advanceReason`：

- 有未过门槛 → `gate`
- 否则 `score < 50` → `match`
- 否则若 `bonusApplied > 0` 且决策分 ≥ 80 而 `matchScore < 80` → `bonus`（可选，供文案区分「匹配本身未到优先、被加分送进去」）
- 否则 → `ok`

排序仍按决策分从高到低。

## 卡片展示

左边大方块始终是决策分。失败态（`level === '错误'`）不渲染任何加分旁注。

填写了加分看（y ≥ 1）时，非失败卡片都要出现具备提示 `加分看 x/y`（x = 具备条数，y = 本岗填写条数）。未填写加分看则整段不加分文案，与现在一致。

### 1. 门槛未过

- 档位「不建议推进」+ 未过门槛列表。
- 旁注：`经历匹配 {matchScore} · 加分看 x/y（未计入）`（经历匹配与决策分相同则省略经历匹配，只留加分看提示）。

### 2. 门槛过了，匹配不足（决策分 &lt; 50）

- 档位「不建议推进」+「经历/技能匹配不足」。
- 旁注：`加分看 x/y（未计入，匹配不足 50）`。
- 不把加分加进大数字。

### 3. 门槛过了，匹配 ≥ 50，加分已计入

- 档位按决策分。
- `bonusApplied > 0` 时旁注：`经历匹配 {matchScore} · 加分 +{bonusApplied}`。
- 若 `matchScore < 80` 且加分后的决策分 `>= 80`，在档位旁单独显示徽标 `加分晋级`，明确此人由加分项从「可推进」跨入「优先推进」。
- `bonusApplied = 0` 但 y ≥ 1 时旁注：`加分看 0/y`（让人知道填了但这个人一条都没具备）。
- 未填加分看且决策分 ≥ 50：不显示经历匹配，也不显示加分（与旧态 1 相同）。

### 4. 评分失败

- 只显示失败原因 + 重评。禁止出现加分看或经历匹配数字。

具备的加分看条目仍可进「具备」列（与经历证据合并时去重、封顶条数沿用现逻辑）。未计入分数时，不要在具备列里写成「+3」，以免和决策分矛盾；分数解释只走旁注。

## Prompt / 缓存

- `matchScoringPromptBlock`：加分看改为「逐条给 bonusKeywordResults；有证据才 met；缺失不扣 matchScore；系统在门槛通过且匹配 ≥ 50 时另计加分，模型不要把加分项计入 matchScore」。
- JSON 合同增加 `bonusKeywordResults`。
- `PROMPT_VERSION` 必须升级，作废旧缓存。

## 合成字段（给展示 / CSV）

`composeFinalScore` 增加并回传：

- `bonusPoints`：理论加分 `min(15, 3 * metCount)`，无论是否计入。
- `bonusApplied`：实际加进决策分的值（0 或 `bonusPoints`）。
- `bonusMetCount` / `bonusTotalCount`
- `bonusKeywordResults`（归一化后）

CSV：现有列保持；「经历匹配」仍是 `matchScore`。不新增列也可以，若加列则放在经历匹配后，名为「加分看」，单元格 `x/y` 或 `+N`。实现时若改 CSV 须同步导出测试；**默认不改 CSV 列**，以免已导出表格对不齐。

## 验收例子（独立推导，禁止用当前输出当期望）

1. 门槛未过 1 条，match 90，加分看 2/2 具备 → 决策分 42，档位不建议推进，旁注含「未计入」。
2. 门槛全过，match 45，加分看 5/5 具备 → 决策分 45，不是 60。
3. 门槛全过，match 50，加分看 1 条具备 → 决策分 53。
4. 门槛全过，match 78，加分看 1 条具备 → 决策分 81，优先推进。
5. 门槛全过，match 78，加分看填写 3 条、0 条具备 → 决策分 78，旁注 `加分看 0/3`。
6. 未填加分看，门槛全过，match 78 → 决策分 78，无加分旁注。
