# Moka 智能简历筛选助手

Chrome 插件：在 Moka 候选人列表页批量拉取简历，核对硬性门槛，并用 AI 评估岗位匹配度与推进档位。

## ✨ 主要功能

- **接口拉取候选人** — 捕获并重放 Moka 列表接口，支持分页与「本轮筛选人数」
- **详情补全经历** — 自动补全实习 / 项目等结构化经历（`practiceInfo` / `projectInfo` 等）
- **硬性门槛** — 学历、院校、经验、性别、年龄等由本地判定；语言、专业及其他由 AI 逐条核对
- **筛选关键词** — 「重点看」定义经历匹配；「加分看」最多 5 项，有证据时每项 +3
- **AI 经历匹配** — 只评价经历、技能与 JD 的对口程度；门槛通过不托到 50 分
- **结果侧栏** — 左侧大数字是用于排序和推进判断的决策分；仅在门槛压分时补充经历匹配，不挡住 Moka 名单
- **多 Provider** — OpenAI / Claude / 自定义（OpenAI 兼容）接口
- **本地存储配置** — API Key 只保存在浏览器本地；本岗配置点保存或开筛时落盘

## 🆕 当前版本要点（v1.9.5）

- **匹配分不再虚高（1.9.5）**：新增「给分锚点」+「理由与分数同向」——四项按证据格局分档（仅相邻/可迁移职责 → 40–50、行业差异大 → 45 以下、关键技能无证据 → 40 以下），理由写「缺少直接经验 / 差异较大」时该项不得超过 50。修复「理由全在说缺口、分数却给 55」的中性化打分。代价：评分缓存一次性失效（`PROMPT_VERSION` v3）
- **校准面板分组 + 近期优先（1.9.4）**：本岗校准建议拆成「规则调整」（可采纳）与「诊断」（只提示，如插件判定偏严 / 偏宽）两组，不再混排；复盘样本按更新时间倒序参与并列打破（不做时间衰减，不改阈值）
- **历史偏好不会变成硬性门槛（1.9.3）**：注入评分的历史偏好说明段明确「历史反馈只用于校准本岗偏好，不得据此创建新的硬性一票否决条件」「简历未提及某项不等于不具备该项」，避免「以前淘汰过类似的人」被误解成一票否决；全岗「反复信号」也改用归一化口径统计。代价是评分缓存一次性失效（`PROMPT_VERSION` v1→v2），下次筛选会重新调用模型
- **本岗校准更准、不误导（1.9.2）**：校准建议先做**信号归一化**再聚合——「没有达人资源 / 缺少达人合作经验 / 无KOL合作经验」算同一个「达人合作」，反复偏好不再被不同说法拆散；写入「重点看」的是**肯定式**文案（不再写「无达人合作」这种反义句）；新增**偏向诊断**（插件判定可能偏严 / 偏宽，只提示不可采纳），替代过去「明明有系统性分歧却报判断较一致」；每条建议附**可信度 高/中/低**；`加入门槛` 会提醒「这是不是真正的一票否决条件」
- **内网连接锁死、模型名放开（1.9.1）**：有 `config.local.js` 时，接口协议 / API 提供商 / Endpoint 三项被锁定为内网值（设置页置灰，防误改）；**模型名称改为默认值兜底，设置页可随时切换**（如同网关的不同模型档位），改完即生效
- **连接配置全面自由化（1.8.9）**：「接口协议」（OpenAI 兼容 / Anthropic Claude）是唯一硬约束；**API 提供商改为自由文本框**（选常用服务自动带出 Endpoint 与模型名，仍可任意改）；**API Endpoint 常显可编辑**（官方 / 中转 / 自建 / 本地 localhost 都行，只填到 `/v1` 会自动补 `/chat/completions`）；API Key 与模型名一如既往自由填写。老配置自动迁移，无需重填
- **结果页首行 = 用时 + 预估花费（1.8.8）**：「用量」行改为「用时 2 分 41 秒 · 预估花费 ¥0.156」——整轮耗时秒级实时刷新、完成即冻结，调用次数与 token 收进运行日志不再上结果页；模型未收录单价时整行隐藏
- **并发降档抗抖 + 可见（1.8.7）**：并发自适应不再「一次抖动就降档」——需连续 2 次过载/超时（中间无成功）才降一档，一次正常出分即清零失败计数，避免偶发 429 把并发从 6 误降到 4；开筛/续筛时运行日志会写明「评分并发 N（设置上限 M）」，降过档时标注原因
- **并发自适应（1.8.6）**：遇到网关 429/5xx 或调用超时自动把并发降一档（8→6→4→3→2），连续成功 10 次再逐档回升；设置页的并发数作为上限。配合单次调用超时 150s、超时最多重试 1 次，避免网关被重试打爆
- **修复双跑（1.8.6）**：续筛过程中重新点「开始筛选」，旧续筛 worker 现在会被立即叫停，不再出现同一候选人被评两遍、并发翻倍
- **失败可见（1.8.6）**：评分失败会标明类型（timeout / overload / network / config / other），不再只是「错误 0 分」
- **评分稳定性（1.8.5）**：评分输出上限提到 8000 tokens（思考型模型如 MiniMax-M2 的思考内容也占这份预算，4000 容易把 JSON 挤断）；识别到 `finish_reason=length` 截断时自动把上限加倍重试一次；自定义/中转端点默认带 JSON 模式，网关不支持时自动去掉该参数降级重试；未闭合的思考块不再被当成 JSON 解析
- **并发可配置（1.8.5）**：设置页「评分并发数」可选 1–8（默认 6），自建网关或本地模型可调大提速，被限流时调小
- **评分诊断日志（1.8.5）**：每条评分日志附输出长度、截断标记、是否含思考、调用次数与解析失败类型，慢与失败一眼可定位
- **单人重评修复（1.8.5）**：此前「重评」把内部包装对象当成模型输出，必然判成评分失败；现已修好
- **结果卡右列「差距」（1.8.4）**：原「未体现」只覆盖「简历没写」一层，而该列还装着确认未过的门槛与待确认项；「差距」与左列「亮点」正反对仗，细分类仍由红色「门槛」/琥珀「待确认」徽章承担
- **配置页扁平分区（1.8.2）**：五个分区去掉卡片壳，改「SVG 图标 + 标题 + 细分割线」连续分区，内容区更高；标题图标全部换成单色线性 SVG；10px 文字地板抬到 11px，数字等宽对齐
- **结果卡细节（1.8.3）**：左列由「具备」改名「亮点」；候选人首次出分时卡片淡入、分数徽章轻弹入（只在「评分中→已出分」时播一次，系统开启「减弱动态效果」时禁用），进度条运行中有低对比流光表示活着；操作按钮 emoji 全部换单色线性 SVG
- **评分体系：四项结构化 + 本地加权合成（1.8.0）**：模型分别给「核心职责 40% / 业务场景 25% / 专业技能 20% / 责任范围 15%」打分并各带理由，插件按固定权重本地合成决策分——分数可解释、不随模型漂移；核心职责弱时保护封顶（<40→≤49、40–59→≤69、60–79→≤84），title 像但活不对口不会被误推
- **门槛三态（1.8.0）**：门槛判 pass / fail / unknown；简历没提及=unknown，不脑补、不扣分，卡片以琥珀色「待确认 · ×××」标出待人工核对项，与红色「未过门槛」区分
- **卡片把握度指标（1.8.0）**：卡面常显「简历信息完整度 N%」与「判断把握 高/中/低」；四项分数与理由收进「评分明细」折叠区，卡面只留结论
- **职位配置存档与自动回填**：每个职位的岗位理解 / 硬性门槛 / 简历关键词自动存档；刷新页面、关闭插件后再进同一职位自动带出。存档带职位身份锚点 + 恢复诊断 + 串档防线（锚名不符拒填、空档按首次进入重新生成），保证「存的哪个岗、回填就是哪个岗」
- **简历推荐对象按职位闭环**：推荐对象按职位锚定，Moka 切页后跟随刷新，旧记录缺职位名章时当场自愈；批量推进按捕获职位重放，不跨职位串岗
- **运行日志与排查快照**：侧栏「运行日志」会话级留存（请求 / 分配 / 筛选 / 评分 / 错误分类，可筛选 / 复制 / 导出）；「复制排查快照」一键导出页面上下文 + 职位存档锚点 + 完整接口流水
- **LLM 用量与费用可见**：结果页显示本轮调用次数 / token / 估算费用（内置价目表，设置页可填自定义单价覆盖）；评分缓存命中单独计数，断点续筛不断账
- **配置页体验**：卡片化分区、硬性门槛两列网格、年龄要求下拉式多选（20-25 / 25-30 / 30-35 / 35+）、「💾 保存并测试」一步完成
- **稳健性加固（1.6.18–1.7.1）**：切岗互斥队列、侧栏初始化分步容错、停止后屏蔽在途评分回写、分页抓取失败自动重试退避、热更新幂等守卫（不二次劫持页面请求）、importScripts 逐个容错、并发评分去重（同候选人并发只调一次模型、不重复扣费）、顶层 DOM 绑定空值守航（safeEl）、XHR 监听防泄漏、lint 门禁覆盖全部入口文件 + no-undef 锁死未定义标识符、桥接消息 nonce 握手防伪造、存储写入失败可观测（跑 `npm run check` 自动执行）

## 📋 系统要求

- Chrome 116+
- 可用的 LLM API Key（OpenAI、Claude 或 OpenAI 兼容服务）
- Moka 账号，并在 `https://app.mokahr.com` 的**候选人列表**页使用

开发时：Node 22+，`npm ci && npm run check`。发版 zip：`npm run pack`（产物在 `dist/`）。

## 🚀 安装步骤

### 1. 克隆或下载

```bash
git clone https://github.com/lzm42727-netizen/moka-resume-plugin.git
cd moka-resume-plugin
```

### 2. 在 Chrome 中加载

1. 打开 `chrome://extensions/`
2. 开启「开发者模式」
3. 「加载已解压的扩展程序」→ 选择本项目文件夹
4. 代码更新后：扩展页点「重新加载」，并**刷新 Moka 页面**

### 3. 配置 API

1. 打开 Moka，点击工具栏插件图标（打开右侧栏）→ 「设置」
2. 填写提供商、Endpoint、API Key、模型名称
3. 填好后点「💾 保存并测试」：保存设置并自动测试 API 连接，成功/失败都会在按钮旁提示

自定义 Endpoint 可填到 `/v1`；插件会按需补全 chat 路径。首次访问新域名时，请允许浏览器弹出的 host 权限。

## 📖 使用指南

1. 打开目标职位的**候选人列表**（如初筛）
2. **（可选）先点开任意一位候选人姓名进入详情一次**，再回列表——自动探测失败时，这样能捕获详情接口（含 `scene`），保证实习 / 项目经历能补全
3. 点扩展图标打开右侧栏 → 「配置」：选职位、正式员工 / 实习生、本轮人数
4. 「岗位理解」可按 JD 刷新；硬性门槛区可预填学历、语言、专业等条件；维护「重点看 / 加分看」后点保存，或直接开筛（会自动落盘）
5. 「开始筛选」，在侧栏「结果」里查看评分；可「导出 CSV」；可用「本岗校准」。点卡片会在 Moka 打开该候选人

## 🎯 评分说明

| 决策分 | 档位 | 说明 |
|---------|------|------|
| 80–100 | 🟢 **优先推进** | 门槛已过且匹配明显强 |
| 50–79 | 🔵 **可推进** | 门槛已过且匹配尚可 |
| 0–49 | 🔴 **不建议推进** | 未过门槛，或匹配分不足 |

计分规则（v1.8.x）：模型对「核心职责 40% / 业务场景 25% / 专业技能 20% / 责任范围 15%」四项分别打分，插件按该权重在本地合成**匹配分**；核心职责弱时保护封顶（`coreDuty < 40` → 匹配分 ≤ 49，`40–59` → ≤ 69，`60–79` → ≤ 84，`≥ 80` 不封顶）。门槛判 pass / fail / unknown 三态：有明确未过门槛时，决策分 = `max(0, 49 − 7 × 未过条数)`；信息不足（unknown）不扣分。门槛全过但匹配分 < 50 时，决策分 = 匹配分；匹配分 ≥ 50 且无未过门槛时，决策分 = `min(100, 匹配分 + 3 × 具备的加分看条数)`（加分最多 15，允许跨过 80 进入优先推进，卡片标注「加分晋级」）。面板「推荐 N」统计可推进与优先推进人数。

**结果卡只显示一个分**（v1.8.1）：卡面只保留决策分；匹配分、四项分数与理由、以及完整计算链（`匹配分 57 ＝ 52×40% + …`、`决策分 28 ＝ 49 − 7 × 3 条未过门槛`）都收进「评分明细」折叠区。卡面另常显「简历信息完整度」与「判断把握」两个把握度指标；未过门槛只在「差距」列出现一次（带红色「门槛」徽章，v1.8.4 起右列由「未体现」改名「差距」），信息不足项以琥珀色「待确认」标出。

## 🐛 故障排除

- **未找到候选人 / 拉取很少**：确认在候选人列表页并刷新；调大「本轮筛选人数」或选「全部」；先让列表加载出搜索请求再筛选。
- **提示先点开候选人 / 经历补不全**：插件会先自动探测详情接口；仍失败时在列表点开任意一人详情一次后重试；看状态是否出现「已补全经历 N 位」。
- **API 连接失败**：检查 Key、Endpoint、网络与配额；用「测试 API」；新域名需授权。
- **无法解析模型返回**：重新加载扩展后重筛（解析失败不写缓存）；可换指令跟随更稳的模型。
- **筛选很慢**：人数 × AI 调用量较大时属正常；可减小本轮人数或点「停止」。
