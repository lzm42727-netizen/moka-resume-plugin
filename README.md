# Moka 智能简历筛选助手

Chrome 插件：在 Moka 候选人列表页批量拉取简历，核对硬性门槛，并用 AI 评估岗位匹配度与推进档位。

## ✨ 主要功能

- **接口拉取候选人** — 捕获并重放 Moka 列表接口，支持分页与「本轮筛选人数」
- **详情补全经历** — 自动补全实习 / 项目等结构化经历（`practiceInfo` / `projectInfo` 等）
- **硬性门槛** — 学历、院校、经验、性别、年龄等由本地判定；语言、专业及其他由 AI 逐条核对
- **筛选关键词** — 「重点看」定义经历匹配；「加分看」最多 5 项，有证据时每项 +3
- **AI 经历匹配** — 只评价经历、技能与 JD 的对口程度；门槛通过不托到 50 分
- **结果侧栏** — 左侧大数字是用于排序和推进判断的决策分；仅在门槛压分时补充经历匹配，不挡住 Moka 名单
- **多 Provider** — OpenAI / Claude / 自定义（OpenAI 兼容）接口
- **本地存储配置** — API Key 只保存在浏览器本地；本岗配置点保存或开筛时落盘

## 📋 系统要求

- Chrome 116+
- 可用的 LLM API Key（OpenAI、Claude 或 OpenAI 兼容服务）
- Moka 账号，并在 `https://app.mokahr.com` 的**候选人列表**页使用

开发时：Node 22+，`npm ci && npm run check`。发版 zip：`npm run pack`（产物在 `dist/`）。

## 🚀 安装步骤

### 1. 克隆或下载

```bash
git clone https://github.com/lzm42727-netizen/moka-resume-plugin.git
cd moka-resume-plugin
```

### 2. 在 Chrome 中加载

1. 打开 `chrome://extensions/`
2. 开启「开发者模式」
3. 「加载已解压的扩展程序」→ 选择本项目文件夹
4. 代码更新后：扩展页点「重新加载」，并**刷新 Moka 页面**

### 3. 配置 API

1. 打开 Moka，点击工具栏插件图标（打开右侧栏）→ 「设置」
2. 填写提供商、Endpoint、API Key、模型名称
3. 「🧪 测试 API」通过后「💾 保存设置」

自定义 Endpoint 可填到 `/v1`；插件会按需补全 chat 路径。首次访问新域名时，请允许浏览器弹出的 host 权限。

## 📖 使用指南

1. 打开目标职位的**候选人列表**（如初筛）
2. **（可选）先点开任意一位候选人姓名进入详情一次**，再回列表——自动探测失败时，这样能捕获详情接口（含 `scene`），保证实习 / 项目经历能补全
3. 点扩展图标打开右侧栏 → 「配置」：选职位、正式员工 / 实习生、本轮人数
4. 「岗位理解」可按 JD 刷新；硬性门槛区可预填学历、语言、专业等条件；维护「重点看 / 加分看」后点保存，或直接开筛（会自动落盘）
5. 「开始筛选」，在侧栏「结果」里查看评分；可「导出 CSV」；可用「本岗校准」。点卡片会在 Moka 打开该候选人

## 🎯 评分说明

| 决策分 | 档位 | 说明 |
|---------|------|------|
| 80–100 | 🟢 **优先推进** | 门槛已过且匹配明显强 |
| 50–79 | 🔵 **可推进** | 门槛已过且匹配尚可 |
| 0–49 | 🔴 **不建议推进** | 未过门槛，或经历 / 技能匹配不足 |

计分规则：有未过门槛时，决策分 = `max(0, 49 − 7 × 未过条数)`；门槛全过但经历匹配低于 50 时，决策分仍等于经历匹配，加分看只提示、不计分；门槛全过且经历匹配 ≥ 50 时，决策分 = `min(100, 经历匹配 + 3 × 具备的加分看条数)`，加分最多 15。加分允许跨过 80 进入优先推进，卡片会标注「加分晋级」。面板「推荐 N」统计可推进与优先推进人数。

## 🐛 故障排除

- **未找到候选人 / 拉取很少**：确认在候选人列表页并刷新；调大「本轮筛选人数」或选「全部」；先让列表加载出搜索请求再筛选。
- **提示先点开候选人 / 经历补不全**：插件会先自动探测详情接口；仍失败时在列表点开任意一人详情一次后重试；看状态是否出现「已补全经历 N 位」。
- **API 连接失败**：检查 Key、Endpoint、网络与配额；用「测试 API」；新域名需授权。
- **无法解析模型返回**：重新加载扩展后重筛（解析失败不写缓存）；可换指令跟随更稳的模型。
- **筛选很慢**：人数 × AI 调用量较大时属正常；可减小本轮人数或点「停止」。
